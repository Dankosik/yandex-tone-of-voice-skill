# Оценка поведения

**Новая редакция: NOT RUN. Модельные сравнительные прогоны не выполнялись.**
Структурные тесты не подтверждают качество русского, отсутствие потерь смысла
в ответах модели, совместимость хостов или скорость работы.

## Наборы

- [evals.json](evals.json): исходные 6 задач; содержат и вход, и ожидания.
- [invocation.json](invocation.json): исходные 20 положительных и отрицательных
  примеров выбора навыка.
- [boundary-prompts.json](boundary-prompts.json): 16 новых самостоятельных входов.
- [boundary-rubric.json](boundary-rubric.json): отдельные ожидания и контрастные пары.

Исходные два файла не изменены. В частности, старая задача 6 сохраняет вопрос
вместо готового hero, когда нет ни доказанной экономии, ни определённых условий.
Это не правило задавать вопрос при любом необязательном пробеле.

Рубрики, expected_output, метки should_trigger и служебные ID не передаются
редактору. Из исходных наборов извлекай только prompt/query. Из нового набора —
только prompt выбранного случая. Не давай агенту этот каталог как справочник.
Примеры в рабочем справочнике иллюстрируют решения, но не служат ответами оценщика.

## Сравнение

Используй одну модель, усилие рассуждения, хост, лимиты и разрешения внутри пары:

1. без навыка;
2. навык на базовом коммите `633a4d9f2dec48483f51097a03e032a817628c55`;
3. новая редакция на конкретном SHA кандидата.

Начинай каждый случай в свежем контексте без соседних ответов. Для изоляции эффекта
отдельно сравни замену точки входа и замену примеров, не приписывая результат
одной правке по сравнению всего пакета. Проверку активации делай с каталогом
доступных навыков без принудительного вызова; редакторские ответы — с зафиксированным
условием загрузки навыка. Число повторов и порядок задай до сравнения.

Сначала оцени смысл: факты, оговорки, степень обещания, регистр, действие CTA,
соблюдение режима и формата. Затем — ненужные вопросы, чтения и пояснения.
Замерь токены или время только при наличии реального trace. Более короткий ответ
с потерянным условием не лучше полного. У допустимых редакций нет единственной
эталонной строки; не оценивай их совпадением текста или числом слов «помощник».

Дословность защищённых строк, число вариантов и длину можно проверять механически
в полученном ответе, но здешние unit-тесты ответы моделей не генерируют и не оценивают.
T12 моделирует недоступность интернета: зафиксируй её в среде, а не называй это
проверкой живого сайта. Для T09 отследи отсутствие вызовов записи и публикации;
обещание модели ничего не менять слабее наблюдаемого trace. Не давай тестам права
на реальные публикации. Подготовленные входы не заменяют проверку реальных хостов.

После локальных контрастов проверь отложенные реальные брифы разных регистров,
не используемые при редактуре инструкций. Сохраняй неудачные ответы наряду с удачными.
