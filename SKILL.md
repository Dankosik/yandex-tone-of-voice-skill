# Yandex Tone of Voice

Веди текст через образ **помощника**: человек приходит с задачей, продукт берёт на себя сложность и приводит к наблюдаемому результату. Это независимая реконструкция по открытым официальным материалам, а не брендбук Яндекса.

## 1. Зафиксируй рамку

Определи восемь позиций:

1. ветвь: `создать`, `адаптировать` или `аудировать`;
2. аудитория;
3. задача человека;
4. формат;
5. подтверждённые продуктовые факты;
6. неизменяемые условия;
7. CTA;
8. регистр из справочника.

Недостающее выведи из материала как минимальное обратимое допущение. Сообщай его только тогда, когда оно заметно меняет результат.

**Критерий завершения:** все восемь позиций определены из запроса, исходника или явно отмеченного допущения.

## 2. Загрузи правила

Полностью прочитай [`references/tone-system.md`](references/tone-system.md) перед работой с любой ветвью.

Прочитай [`references/source-map.md`](references/source-map.md), когда пользователь просит доказать происхождение правила, сравнить текст с реальными продуктами Яндекса или использовать изменчивый факт о продукте Яндекса. Изменчивый факт проверь на актуальной официальной странице и датируй; неподтверждённый факт исключи из результата.

**Критерий завершения:** обязательный справочник прочитан; каждый требуемый текущий факт подтверждён официальным источником либо исключён.

## 3. Выполни выбранную ветвь

### Создать

Построй каждый запрошенный блок по цепочке `задача → действие помощника → результат → доказательство или условие → следующий шаг`. Используй только подтверждённые факты и условия. Верни готовый текст первым; после него допустимы до трёх примечаний о существенных допущениях или доказательных пробелах.

**Критерий завершения:** запрошенная структура и CTA присутствуют; каждый блок несёт одну мысль; каждое утверждение опирается на входные данные или проверенный источник.

### Адаптировать

До переписывания составь внутренний реестр фактов, обещаний, обязательных оговорок и требуемых структурных элементов. Затем перестрой текст по цепочке помощника и верни адаптацию первой. После неё допустимы до трёх примечаний о намеренно сохранённых ограничениях.

**Критерий завершения:** каждый элемент реестра сохранён без усиления; запрошенная структура сохранена; CTA стал конкретным либо отмечен как фактологически неразрешимый.

### Аудировать

Сохрани read-only режим: сканируй каждый блок по проверке из справочника и возвращай только замечания. Для каждого замечания дай `цитата или блок → правило → последствие → минимальное направление`. Фактические, доказательные, правовые и чувствительные риски вынеси отдельно. Готовую замену давай только по прямому запросу.

Формат:

```markdown
Вердикт: [близко / частично близко / не близко]

1. [Блок или цитата] — [нарушенное правило и последствие]
   Направление: [минимальная правка]

Риски:
- [факт, доказательство, ограничение или чувствительная категория]
```

**Критерий завершения:** каждый блок исходника проверен; каждое замечание содержит четыре элемента; риски отделены от стилистических расхождений; переписанный вариант отсутствует без прямого запроса.

## 4. Закрой проверку

Прогони результат по разделу «Приёмка» в [`references/tone-system.md`](references/tone-system.md). Исправь каждый провал, который позволяет ветвь; оставшийся фактический пробел назови рядом с затронутым утверждением. Для собственного продукта обозначь стиль как независимую реконструкцию, если публикационный контекст может создать впечатление официальной связи с Яндексом.

**Критерий завершения:** каждый применимый пункт приёмки проходит либо имеет явно названный доказательный пробел; формат соответствует выбранной ветви.
